# Dataset Registry

Every dataset in this course is documented here — source, licence, known quirks. This is Module 1's lesson applied to our own course: *if you can't say where data came from and what's wrong with it, you shouldn't be analysing it.*

> **All five datasets are SYNTHETIC.** They are generated by `generate_datasets.py` (seed 42), designed to be realistic in shape, scale and Indian market convention — but they are **not real market data**. This is deliberate: real data licences restrict redistribution, and synthetic data lets us plant *exactly* the defects we want learners to find. Modules 3, 6 and 9 additionally teach learners to pull **real** NSE data live via `yfinance`.

## 1. `nifty50_prices.csv`

| Field | Value |
|---|---|
| **Shape** | 1,277 rows × 6 cols |
| **Grain** | One row per NSE trading day, 2021-01-01 → 2025-12-31 |
| **Columns** | `date`, `open`, `high`, `low`, `close`, `volume` |
| **Units** | Index level (points); volume in contracts |
| **Realism** | Starts ~14,000, ends ~18,400 (+5.5% p.a.), max drawdown −29.8%, regime shift to higher volatility at ~45% through the series |
| **Used in** | M0 (first chart) · M3 (EDA) · M4 (charts) · M6 (forecasting) · M9 (time series) · M10 (Monte Carlo) |

**Known quirks (deliberate):**
| # | Quirk | Teaches |
|---|---|---|
| a | `volume` is blank for all of 2021 (257 rows) | Completeness — *field*-level missingness |
| b | 2023-06-14 and 2024-02-21 silently absent | Completeness — *row*-level missingness (and that it's invisible unless you check the calendar) |
| c | 2024-08-13 `high` is 10× the close (fat-finger) | Accuracy — the impossible-value check |
| d | Diwali Muhurat sessions present on holiday dates (2022–2025) | The false positive: looks like an error, is actually a real half-session. Domain knowledge beats the outlier rule |

## 2. `messy_transactions.csv`

| Field | Value |
|---|---|
| **Shape** | 5,060 rows × 8 cols |
| **Grain** | One retail bank/UPI transaction, Jan 2024 – Jun 2025 |
| **Columns** | `txn_id`, `txn_date`, `customer_id`, `merchant`, `category`, `mode`, `amount_inr`, `city` |
| **Units** | ₹ (INR) |
| **Links to** | `client_book.csv` on `customer_id` = `client_id` |
| **Used in** | M1 (Trust Report, no code) · M3 (cleaning) · M3.5 (SQL joins) · M5 (diagnostics) |

**Known quirks (deliberate — this is the teaching dataset for data cleaning):**
| # | Quirk | Count | Teaches |
|---|---|---|---|
| a | Three date formats mixed: `2024-07-20`, `04/02/2025`, `Jan 12, 24` | ~40% non-ISO | Date ambiguity — is `04/02/2025` Feb 4 or Apr 2? |
| b | Exact duplicate rows (double-posting incident) | 54 | Deduplication |
| c | `category` missing | 190 | Missing-field handling |
| d | Same merchant, different strings (`Amazon India` / `amazon india`, `BigBazaar` / `BIG BAZAAR`) | ~140 | Entity resolution / consistency |
| e | 12 rows are USD amounts, unmarked (appear ~83× too small) | 12 | Currency contamination — the silent killer |
| f | Zero-amount (15) and negative-amount (8) rows | 23 | Impossible values |
| g | `txn_date` = `1970-01-01` | 9 | Unix-epoch default = missing timestamp, not time travel |
| h | `city` with padding/caps: `" MUMBAI "` | 120 | Whitespace & case normalisation |

## 3. `client_book.csv`

| Field | Value |
|---|---|
| **Shape** | 1,000 rows × 11 cols |
| **Grain** | One wealth-management client |
| **Columns** | `client_id`, `onboard_date`, `city`, `segment`, `risk_profile`, `aum_inr`, `products_held`, `tenure_months`, `sip_active`, `relationship_manager`, `churned` |
| **Units** | ₹ (AUM), months (tenure) |
| **Used in** | M3 (groupby/merge) · M3.5 (SQL joins) · M5 (cohort analysis) · M8A (asset-management stream) |

**Built-in structure (so analysis finds something real):**
- Churn rate **20.4%** overall, with a genuine, discoverable gradient: **tenure** (28% churn in the newest quartile → 12% in the oldest) and **products held** (more products → less churn) and **segment** (Mass 25% vs Affluent 13%)
- AUM is log-normal by segment: Mass ≈ ₹6.5 lakh median → Ultra-HNI ≈ ₹6.4 crore median

**Known quirks:** 28 missing `risk_profile`, 6 missing `aum_inr`.
**Survivorship note (M1 callback):** churned clients remain in the file with AUM frozen at exit. If a learner filters to `churned == 0` and reports "average client AUM," they have just committed survivorship bias — this is an intentional trap used in M5.

## 4. `company_financials.csv`

| Field | Value |
|---|---|
| **Shape** | 10 rows × 17 cols |
| **Grain** | One fiscal year, FY16-17 → FY25-26, for fictional Indian retailer **"MoneyMart India"** |
| **Columns** | Full P&L waterfall: `revenue_cr` → `cogs_cr` → `gross_profit_cr` → opex lines → `ebitda_cr` → `ebit_cr` → `pbt_cr` → `pat_cr`; plus `stores_count`, `avg_ticket_size_inr`, `revenue_cr_as_first_reported` |
| **Units** | ₹ crore (P&L lines), ₹ (ticket size) |
| **Used in** | M4 (waterfall/bridge charts) · M5 (variance walk) · M6 (regression) · M8B (DCF valuation) |

**Verified integrity:** the P&L adds up — `revenue − cogs = gross_profit` and `gross − opex lines = ebitda` both hold to ±0.15 cr. Learners can and should check this.

**Known quirks (deliberate):**
| # | Quirk | Teaches |
|---|---|---|
| a | Revenue *dips* in FY20-21 and FY21-22 (COVID), then re-accelerates | Regime change — fitting a single trend across this is wrong |
| b | `revenue_cr_as_first_reported` for FY20-21 is 3,511 cr vs restated `revenue_cr` of 3,366 cr | **Point-in-time bias** — which number did the market actually see in 2021? |

## 5. `nse_stock_universe.csv`

| Field | Value |
|---|---|
| **Shape** | 20,360 rows × 5 cols (long format) |
| **Grain** | One ticker × one trading day, 2022-01-03 → 2025-12-31 |
| **Columns** | `date`, `ticker`, `sector`, `close`, `volume` |
| **Universe** | 20 large-cap NSE tickers across 11 sectors — RELIANCE, TCS, HDFCBANK, INFY, ICICIBANK, HINDUNILVR, ITC, SBIN, BHARTIARTL, KOTAKBANK, LT, AXISBANK, ASIANPAINT, MARUTI, TATAMOTORS, SUNPHARMA, TITAN, WIPRO, NESTLEIND, POWERGRID (all `.NS`) |
| **Used in** | M9 (time series) · M11 (backtest) · M12 (portfolio optimisation) |

**Built-in structure (so the finance actually works):**
- Mean pairwise return correlation **0.26**, annualised vol **16%–51%** across names
- **Diversification is visibly real:** average single-stock vol 23.7% vs equal-weight portfolio vol 12.5% — the exact demonstration Module 12 needs before introducing the efficient frontier
- Returns are built from a market factor + sector factor + idiosyncratic noise, so sector clustering shows up in a correlation heatmap

**Known quirk (deliberate):** `TATAMOTORS.NS` has an **unadjusted 1:5 stock split on 2024-09-02** — the price drops from ~₹406 to ~₹83 overnight. A naive returns calculation shows a −80% single-day "crash." This is Module 1's adjusted-vs-unadjusted lesson, live in the data, and it will silently wreck any backtest or optimisation that ignores it.

python generate_datasets.py     # writes all five CSVs to data/, seed=42, fully reproducible
